# ⏰ Таймер обратного отсчёта (Node.js)

Консольное приложение, которое ждёт заданный промежуток времени и затем
пишет в консоль, что таймер прозвонил. Пока приложение работает, оно
ничего не выводит — сообщение появляется ровно в момент срабатывания.

Внешних зависимостей нет, достаточно установленного Node.js.

## 📁 Структура проекта

```
4_dfiz_timer/
└── index.js        # разбор аргументов, проверки и запуск setTimeout
```

## 🚀 Использование

```bash
node index.js <секунды>
node index.js <число> <единица> [<число> <единица> ...]
```

### Примеры

```bash
$ node index.js 5
# через 5 секунд:
Таймер прозвонил

$ node index.js 2 минуты
Таймер прозвонил

$ node index.js 1 час 5 минут 10 секунд
Таймер прозвонил
```

## 📋 Форматы времени

| Формат                | Пример                              | Что значит          |
|-----------------------|-------------------------------------|---------------------|
| одно число            | `node index.js 30`                  | 30 секунд           |
| пары «число + единица»| `node index.js 2 минуты 30 секунд`  | 2 мин 30 с          |

### Доступные единицы

| Единица                        | Варианты написания                | Миллисекунды |
|--------------------------------|-----------------------------------|--------------|
| секунды                        | `секунда`, `секунды`, `секунд`, `с`, `сек` | 1000 |
| минуты                         | `минута`, `минуты`, `минут`, `м`, `мин`    | 60 000 |
| часы                           | `час`, `часа`, `часов`, `ч`                | 3 600 000 |

Регистр не важен: `1 ЧАС` и `1 час` работают одинаково.
Дробные значения допускаются: `1.5 часа` — это 90 минут.

## ⚙️ Как это работает

1. `process.argv.slice(2)` отбрасывает путь к `node` и путь к скрипту,
   оставляя только аргументы пользователя.
2. Если аргумент один — он считается количеством секунд и умножается на 1000.
3. Если аргументов несколько — они идут парами «число + единица»:
   `parseDurationPairs` шагает по массиву с шагом 2, переводит каждую пару
   в миллисекунды через `UNIT_TO_MS` и суммирует результат.
4. Итог проверяется на предел `setTimeout` (`2_147_483_647` мс ≈ 24,8 дня).
5. Сумма передаётся в `setTimeout`, а в колбэке печатается сообщение.

## 🛡️ Обработка ошибок

Приложение пишет причину в `stderr` и завершается с кодом `1`, если:

- аргументы не переданы вообще;
- значение не является числом (`abc`, пустая строка, `Infinity`);
- число отрицательное;
- для числа не указана единица измерения (`1 час 5`);
- после числа стоит другое число вместо единицы (`5 6`);
- единица измерения неизвестна (`1 неделя`);
- итоговое время больше предела `setTimeout`.

Примеры:

```bash
$ node index.js -5
Ошибка: время в секундах ("-5") не может быть отрицательным

$ node index.js 1 час 5
Ошибка: для "5" не указана единица измерения

$ node index.js 5 6
Ошибка: после числа "5" ожидается единица измерения, а получено "6"

$ node index.js 1 неделя
Ошибка: неизвестная единица измерения "неделя"
```

## ⚠️ Ограничения

- Уведомление только через консоль: если не смотреть в консоль,
  срабатывание можно пропустить. Другие способы уведомления появятся позже.
- `setTimeout` гарантирует «не раньше», поэтому реальная задержка может быть
  на несколько миллисекунд больше заданной.
- Максимум — около 24,8 дня: большее время `setTimeout` не принимает.

## 🧠 Используемые концепции

- **`process.argv`** — аргументы командной строки.
- **`setTimeout`** — отложенный вызов колбэка.
- **`Map`** как словарь «единица → миллисекунды».
- **Исключения** (`throw` / `try...catch`) для проверки входных данных.
- **`process.exit(code)`** — корректный код возврата для shell и CI.
